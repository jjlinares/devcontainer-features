# Dev Container Features

Personal Dev Container Features published under `ghcr.io/jjlinares/devcontainer-features`.

## browser-automation

Installs one exact, checksum-verified full Chrome for Testing build. It can optionally install one exact, checksum-verified standalone `agent-browser` binary configured to use that Chrome.

```jsonc
{
  "features": {
    "ghcr.io/jjlinares/devcontainer-features/browser-automation:1.0.0": {
      "installAgentBrowser": true
    }
  }
}
```

Use a complete Feature version or OCI digest—not mutable `:1`. The current tested pair is Chrome for Testing `151.0.7922.76` and agent-browser `0.33.2`. Supported target: Debian/Ubuntu-based Linux AMD64.

Feature application belongs in CI image construction. Runtime devcontainers should consume the prebuilt image without declaring the Feature again.

Detailed behavior and non-goals: [`src/browser-automation/NOTES.md`](src/browser-automation/NOTES.md).

## pi-coding-agent

Installs the latest Pi coding agent after adding Node.js 24 through the official Node Feature. It mounts host `~/.pi/agent`, activates available setup resources, and stores sessions under `.pi/sessions` in the workspace by default.

Opt in through VS Code User Settings rather than a project repository:

```jsonc
{
  "dev.containers.defaultFeatures": {
    "ghcr.io/jjlinares/devcontainer-features/pi-coding-agent:1.0.1": {}
  }
}
```

The Feature owns the host mounts. Available settings, authentication, instructions, skills, prompts, themes, and extensions are activated through symlinks without copying. Trust, caches, binaries, package installs, and history remain container-local. Override workspace session storage with `sessionDir`.

Detailed behavior: [`src/pi-coding-agent/NOTES.md`](src/pi-coding-agent/NOTES.md).

## Local verification

Requires Docker and the Dev Container CLI `0.88.0`:

```bash
npm install -g @devcontainers/cli@0.88.0

# Repository-local temp storage is required by some Docker Desktop setups.
mkdir -p .tmp
export TMPDIR="$PWD/.tmp"

# Creates only missing Pi test prerequisites; existing host Pi resources are not replaced.
./scripts/prepare-pi-feature-test-host.sh

devcontainer features test --skip-scenarios -f browser-automation \
  -i mcr.microsoft.com/devcontainers/base:ubuntu -u vscode .

devcontainer features test -f browser-automation \
  --skip-autogenerated --skip-duplicated .

# Pi generated-default and duplicate-install tests.
devcontainer features test --skip-scenarios -f pi-coding-agent \
  -i mcr.microsoft.com/devcontainers/base:ubuntu -u vscode .

# Pi host-setup and Python-image scenarios.
devcontainer features test -f pi-coding-agent \
  --skip-autogenerated --skip-duplicated .

rm -rf .tmp
```

Each Feature has a generated-default/duplicate-install command and an explicit-scenarios command. Scenarios cover browser control as a non-root user, mounted Pi setup, and installing Pi on a Python image.
